# VibeBubble 产品说明

> 从一个灵感，到一个真实作品。

## 1. 产品是什么

VibeBubble 是面向设计师、独立开发者与内容创作者的 AI 创作孵化平台。它把分散在各平台的优质 AI 作品整理成可检索的灵感库，提供轻量的灵感记录方式，并用原创的「八步创造法」配合 AI，把一条模糊的想法逐步推进为可展示、可发布的作品。

与「AI 生成一次内容」不同，VibeBubble 关注的是创作的完整过程：发现 → 记录 → 孵化 → 沉淀。

## 2. 面向谁

- 有想法、但不知道从哪里开始的独立创作者
- 需要持续找选题、找方向的内容创作者
- 想用 AI 把原型真正做出来的设计师与开发者
- 正在学习产品创造的初学者

## 3. 一条完整的创作路径

1. **发现**：在灵感库浏览真实案例，按领域、载体、来源筛选，进入详情查看作者与原始出处。
2. **记录**：用一句话或一段语音，把当下的灵感存入个人空间。
3. **孵化**：从灵感创建项目，按八步逐步推进，每一步由 AI 结合项目上下文给出任务与提示词。
4. **沉淀**：每个阶段的产出可编辑、可回滚、可导出，形成项目完整的过程档案。

## 4. 核心功能

### 4.1 Explore 灵感库

真实 AI 作品以气泡形式呈现，支持搜索、按领域与载体筛选、随机探索和详情查看。每个案例保留作者、来源平台和原始链接，解决案例散落在小红书、抖音、B站、Reddit、GitHub，靠收藏夹和截图无法复用的问题。

### 4.2 Ideas 灵感记录

- Web 端一句话回车即记，描述与标签选填，可一键「开始孵化」。
- 硬件 AI Passport 按下说话，15 秒内的语音上传后自动转写，生成灵感卡片并进入同一个灵感库。
- 同一用户 10 分钟内的重复内容自动去重。
- 灵感默认私有，只有本人可见。

### 4.3 Create 八步孵化

从一个灵感创建项目后，按「认知、探索、定位、分析、设计、实现、运营、迭代」八个阶段推进。每个阶段包含核心问题、建议行动和阶段产出；阶段可跳过、可回退，也可以循环。

点「AI 解析」后，系统结合项目背景与已有材料，生成阶段判断、要点表、4–5 条可勾选任务、2–3 张知识卡片，以及一段可直接复制的提示词。

### 4.4 Projects 阶段产出

- 阶段产出可编辑、保存，支持合并更新、整体替换、恢复上一版本。
- 每一轮产出只读留痕，可随时回看。
- 支持导出本轮 Markdown。
- 项目可退回灵感库继续沉淀，也可连同灵感一起删除。

### 4.5 内容运营闭环

后台支持从小红书、抖音、Reddit 采集内容：用浏览器书签保留用户登录态导出 JSON，多文件导入后按评论去重，AI 按固定标准抽取产品名、摘要、分类和原文证据，人工勾选后批量发布。来源、作者和原始链接完整保留。

## 5. 八步创造法

| 阶段 | 这一阶段做什么 | 阶段产出 |
|---|---|---|
| 01 认知 | 理解领域的基本概念、运行机制与关键要素，区分事实与假设 | 认知简报：领域概述、关键要素、初步判断与待了解问题 |
| 02 探索 | 通过案例、用户、场景与跨领域观察，发现不同做法和未被满足的需求 | 探索记录：参考案例、场景发现、机会方向与待验证问题 |
| 03 定位 | 结合机会、个人优势、资源与约束，明确为谁解决什么问题 | 定位简报：目标人群、核心场景、价值主张与本轮范围 |
| 04 分析 | 分析用户、需求、场景、市场、竞争与可行性，识别关键风险 | 分析简报：关键需求、依据、风险假设与验证计划 |
| 05 设计 | 把定位与洞察转化为可执行方案，用草图和原型检查 | 设计方案：核心流程、关键界面、设计规则与交付清单 |
| 06 实现 | 通过开发与制作，让方案成为可运行、可体验的产物 | 可运行产物与测试记录 |
| 07 运营 | 让目标用户认识并使用成果，观察触达、转化与反馈 | 运营记录：渠道、反馈与有效做法 |
| 08 迭代 | 对照目标回顾结果，明确保留、调整与停止的事项 | 迭代结论与下一轮行动 |

## 6. AI 在其中的角色

- **阶段解析**：结合项目上下文生成阶段判断、任务清单、知识卡片和提示词，输出经固定 schema 清洗后入库，前端只消费校验通过的数据。
- **内容准入**：采集到的评论先由规则过滤空内容、纯表情、纯链接和提问，再由模型抽取产品名、摘要、分类与原文证据；服务端二次校验「产品名存在且不少于 2 字」，不通过不发布。分数只用于排序，不作为准入。
- **边界**：提示词明确禁止编造原文没有的产品名、数据或成果；信息不足时标注「待验证」「待补充」；模型输出不直接展示。

## 7. 技术架构

- **前台**：原生 HTML / CSS / JavaScript（ES Modules），通过 Supabase Auth 与 REST 访问数据
- **后台**：Next.js + TypeScript + Tailwind，部署在 Vercel
- **数据**：Supabase Postgres / Auth / Storage / Edge Functions，启用 RLS
- **AI**：DeepSeek API（固定 JSON 输出），由 Edge Functions 与 Route Handlers 调用
- **采集**：Python + Playwright，以及浏览器书签（复用用户登录态）
- **硬件**：AI Passport，音频限制 15 秒 / 480 KB，云端转写后生成灵感卡片，10 分钟时间窗去重
